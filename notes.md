# Event operations

- Event date, venue, judging timings, and badge dimensions live in `src/eventDetails.js` so public and organizer views stay in sync.
- Set `ORGANIZER_PASSWORD_HASH` in the local environment and Render before using `/organizer`. Generate a salted hash locally with `npm run organizer:hash-password`; never store the plaintext password in the repository. Changing the hash invalidates existing organizer sessions.
- Accept applicants with `npm run applicants -- list` (who hasn't been emailed yet; `--all` shows everyone), then `npm run applicants -- accept <id>... ` or `npm run applicants -- accept --all-pending`. Without `--send` it is a dry run that changes nothing and saves an email preview to `prints/`. With `--send` (and `RESEND_API_KEY` and `EMAIL_FROM` copied into the local `.env`) it asks for confirmation, marks them accepted, and emails each one once, recording `acceptance_email_sent_at`; re-running skips anyone already emailed. It refuses to accept anyone after `rsvpDeadline`, and to send before the waiver/RSVP update is deployed. Resend's free plan sends 100 emails a day; if the daily limit is hit, run the same command again the next day. `printed` defaults to `FALSE`, and `meal_count` to `0`.
- New applications close at `applicationsCloseAt` in `src/eventDetails.js` (end of November 8, Toronto time). After that, sign-up still works, but the dashboard's Apply button is greyed out, `/apply` shows "Applications closed", and the API refuses new applications. Existing applicants are unaffected.
- After the RSVP deadline, or after a waiver reset, hackers can't RSVP themselves: once their waiver is in, click **Confirm RSVP** on `/organizer`.
- A second meal scan of the same badge within `mealScanCooldownMinutes` (30) shows "Already recorded" and isn't counted, so rescanning after a dropped connection is safe.
- Accepted hackers upload their signed waiver (PDF, JPG, or PNG; up to 4 files of 5 MB each; photos are shrunk in the browser) from the dashboard. Submitting it unlocks the RSVP button, which closes at `EVENT_DETAILS.rsvpDeadline`. The participant pass (meal QR) and badge printing are only for hackers who have RSVP'd. Files are stored in the `waiver_files` table, can only be downloaded from `/organizer`, and are deleted automatically `waiverRetentionDays` after upload. Resetting a waiver on `/organizer` deletes its files and the RSVP so the hacker can upload again.
- `/organizer` scans meal QRs, imports a full Devpost Projects data CSV, and assigns projects once. Include personally identifiable information so team emails can be matched to accepted applications. Only `Submitted` projects are imported; drafts are skipped. Re-imports replace the previous roster, so correct mismatched emails in the CSV and re-import before locking assignments.
- Judges use `/judges`, a separate black-and-white panel. They sign in with their full name and the shared judge password. The password is stored only as a scrypt hash in the database's `app_settings` table, never in this public repository; set or change it with `npm run judges:set-password` (it uses the `DATABASE_URL` in the local `.env`). Changing it signs every judge out within 30 seconds. Importing the Devpost CSV on `/organizer` fills the panel with every submitted project, including its description, team names, built-with tags, demo and try-it links, and opt-in prizes. Each judge rates each project 1-5 and can add a comment; both save as they go. Ratings are keyed by the project's Devpost URL, so re-importing keeps them. Organizers see every rating and comment, ranked by average, under "Judging results" on `/organizer`.
- The October 18 Devpost CSV in the repository root contains synthetic QA projects, not real submissions. Never import it into production; replace it with a fresh Devpost export after submissions close. Project exports named `projects-*-with-pii-*.csv` are ignored by Git.
- Assignment previews default to two rooms (Room 1 and Room 2) and 17:30-20:00, matching the schedule; change `defaultJudgingRooms`, `defaultJudgingStart`, or `judgingWindowMinutes` in `src/eventDetails.js` if it moves. Each project gets five minutes to pitch plus one minute for changeover. Room count and start time can be changed until the one-time assignment is confirmed; overtime requires explicit confirmation. Every submitted project gets a slot; projects with unmatched or duplicate team members need a "Schedule them anyway" confirmation, and those hackers won't see their time on their pass. Imports are blocked after assignments are locked.
- Run `npm run badges:generate` locally for Letter sheets, `npm run badges:generate -- tabloid` for Tabloid sheets, or `npm run badges:generate -- a4` for A4 sheets (landscape, two badges per sheet, because portrait A4 is too narrow for two 4-inch badges). Set a reachable `DATABASE_URL` in the local `.env` first. The command exports badges for confirmed (RSVP'd), unprinted participants with `lanyard_design.png` into the git-ignored `prints/` folder. Letter holds two 4x6-inch badges per sheet; Tabloid holds four, with a 0.125-inch gutter. It marks only those applications `printed = TRUE` after the PDF is safely written to disk. Reset `printed` to `FALSE` in PostgreSQL for a replacement badge. Print at actual size, not "fit to page."
- The same opaque QR value appears on the badge and `/participant`. Only an authenticated organizer scan can increment the meal count.
- Participant names are capitalized for display on badges, passes, meal scans, and the dashboard; original application names remain unchanged in PostgreSQL.
- Badge names use bundled Noto fonts for East Asian, Korean, Arabic, Devanagari, and Hebrew scripts, including mixed-script names. Their SIL OFL license files are in `public/fonts/`. The participant pass refreshes while visible, clears after access is revoked, and can also be refreshed manually.
- The app no longer uses the legacy `event_applications.status` field. Existing databases may still have it; inspect production values and external queries before dropping that column. Keep the `/login` and `/register` redirects, existing-database migrations, and Google-account repair until their compatibility needs are verified.
